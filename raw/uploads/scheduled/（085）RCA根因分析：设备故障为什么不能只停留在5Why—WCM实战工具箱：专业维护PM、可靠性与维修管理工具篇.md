# 一、总述

**RCA根因分析不是简单连续问五个“为什么”，也不是在故障报告中把5Why表格填满，而是通过事实收集、过程还原、失效机理分析、证据验证、系统原因追溯和防再发措施设计，找到设备故障真正可控制、可改善、可验证的根本原因。**

很多企业做设备故障分析时，最常用的工具就是5Why。5Why简单、直观、容易推广，适合班组和现场快速追问问题。但在设备故障尤其是复杂故障、重复故障、重大故障中，如果只停留在5Why，常常会出现以下问题：

* 问到第三层就写“点检不到位”；
* 问到第四层就写“培训不足”；
* 问到第五层就写“管理不到位”；
* 每一层之间缺少事实证据；
* 故障机理没有讲清楚；
* 部件为什么失效没有分析；
* 为什么没有提前发现没有分析；
* 为什么PM没有防住没有分析；
* 为什么同类设备没有横展没有分析；
* 对策仍然是“加强点检、加强培训、加强考核”。

这说明一个问题：

> **5Why是RCA的一种追问方法，但不是完整的RCA体系。**

一句话判断：

> **RCA的本质，不是把“为什么”问够五次，而是用证据把故障从现象追溯到技术根因、管理根因和体系根因，并转化为能够防止再发的标准、策略和改善措施。**

---

## 二、工具定义

**RCA，Root Cause Analysis，根因分析，是针对设备故障、质量异常、安全事件、环保异常、重复问题和重大损失，通过系统化方法识别根本原因并制定防再发措施的分析工具。**

在设备故障管理中，RCA通常要回答六个问题：

| 问题 | 说明 |
| --- | --- |
| 发生了什么 | 故障现象、时间、设备、部位、工况、影响 |
| 为什么发生 | 技术机理、部件失效、工况异常、维修质量 |
| 为什么没有提前发现 | 点检、状态监测、报警、操作观察是否失效 |
| 为什么没有被预防 | PM、润滑、紧固、备件、操作标准是否缺失 |
| 为什么允许重复发生 | 管理流程、标准、培训、审核、横展是否不足 |
| 如何防止再发 | 技术、点检、PM、操作、备件、管理措施闭环 |

### RCA与5Why的关系

| 项目 | 5Why | RCA |
| --- | --- | --- |
| 工具属性 | 原因追问工具 | 系统性根因分析方法 |
| 适用对象 | 简单问题、单一因果问题 | 复杂故障、重复故障、重大损失问题 |
| 分析重点 | 沿因果链追问为什么 | 事实、机理、证据、系统、措施闭环 |
| 风险 | 容易主观跳步、停在管理口号 | 需要数据、证据和跨专业协同 |
| 输出 | 原因链和对策 | 根因、验证证据、防再发措施、标准更新 |
| 关系 | 是RCA常用方法之一 | RCA可包含5Why、鱼骨图、故障树、PM分析等 |

判断标准：

> **5Why可以帮助追问原因，但RCA必须保证每一层原因都有事实依据、逻辑关系和验证证据。**

---

## 三、工具用途

### 1. 防止故障分析停留在表面原因

设备故障分析最常见的问题，是把表面现象当原因。

例如：

| 表面原因 | 还要继续追问 |
| --- | --- |
| 轴承损坏 | 为什么轴承损坏？润滑、污染、安装、载荷是否异常？ |
| 油管破裂 | 为什么油管破裂？磨损、老化、振动、布管是否异常？ |
| 电机烧损 | 为什么过热或过载？保护、散热、负荷、电源是否异常？ |
| 传感器误动作 | 为什么误动作？污染、松动、位置、防护是否异常？ |
| 螺栓松动 | 为什么松动？振动、扭矩、防松、点检是否有效？ |
| 皮带跑偏 | 为什么跑偏？导料、滚筒、张紧、托辊、清扫器是否异常？ |

判断标准：

> **RCA不能把“坏了什么”当成“为什么坏”。坏了什么是故障结果，为什么坏才是分析对象。**

---

### 2. 区分技术原因、检测原因和管理原因

完整的设备故障RCA，通常不能只分析一个层面。

### RCA三层原因逻辑

| 层级 | 分析问题 | 示例 |
| --- | --- | --- |
| 技术层 | 故障为什么发生 | 轴承因润滑不足和粉尘进入导致磨损加剧 |
| 检测层 | 为什么没有提前发现 | 点检表只有“有无异响”，没有温度和振动趋势 |
| 管理层 | 为什么体系允许发生或重复发生 | 润滑标准未定义油量和周期，PM未覆盖该故障模式 |

这三个层级对应设备管理中非常关键的三个问题：

1. **故障发生机理是什么？**
2. **为什么点检和监测没有提前发现？**
3. **为什么PM和管理体系没有提前预防？**

判断标准：

> **只分析技术原因，可能解决一次故障；同时分析检测原因和管理原因，才能提升体系能力。**

---

### 3. 防止对策空泛化

如果RCA停留在5Why表格，常见对策容易写成：

* 加强培训；
* 加强点检；
* 加强检查；
* 加强考核；
* 提高责任心；
* 严格执行制度；
* 要求维修人员注意；
* 要求操作人员认真。

这些对策通常难以验证，也难以防止再发。

### RCA要求对策具体化

| 空泛对策 | RCA要求的具体对策 |
| --- | --- |
| 加强点检 | 增加轴承温度实测值，每班记录趋势，超过70℃挂牌处理 |
| 加强润滑 | 明确润滑点编号、油品、油量、周期、责任人和确认方式 |
| 加强培训 | 制作OPL，现场训练油管磨损识别，培训后实操认证 |
| 加强检查 | 班组每日检查防松标线，点检员每周复核并记录 |
| 加强管理 | 修改PM计划，增加压差报警后滤芯更换工单 |
| 提高责任心 | 建立异常未闭环升级机制，明确响应时限和责任 |

判断标准：

> **RCA对策必须具体到对象、动作、标准、责任、期限和验证指标。**

---

### 4. 支撑PM、点检和维修策略优化

RCA不是独立报告，而是PM体系优化的重要输入。

一次RCA完成后，至少要检查以下内容是否需要更新：

| 更新对象 | 关注内容 |
| --- | --- |
| 点检标准 | 是否增加点位、方法、频次和异常基准 |
| 润滑标准 | 是否更新油品、油量、周期、工具和责任 |
| PM计划 | 是否增加、删除、调整任务和周期 |
| 维修标准 | 是否增加拆装、对中、扭矩、试车要求 |
| 备件策略 | 是否调整安全库存、质量标准、替代件 |
| 状态监测 | 是否增加温度、振动、油液、压力趋势监测 |
| 操作标准 | 是否增加工况控制、启动停止、异常处理要求 |
| 培训材料 | 是否形成OPL、案例库和技能认证内容 |

判断标准：

> **RCA如果没有反向更新PM和点检标准，就很难真正防止再发。**

---

### 5. 支撑重复故障治理

重复故障是RCA最重要的应用场景之一。

重复故障说明：

* 原来维修只修复了结果；
* 原来对策没有命中根因；
* 点检没有提前发现；
* PM没有防住；
* 标准没有更新；
* 同类设备没有横展；
* 管理闭环没有形成。

### 重复故障RCA重点

| 分析方向 | 追问 |
| --- | --- |
| 同一部位 | 为什么该部位反复失效 |
| 同一故障模式 | 为什么同一失效条件持续存在 |
| 同一工况 | 是否与负荷、温度、粉尘、速度有关 |
| 同一备件 | 是否备件质量或选型问题 |
| 同一维修方式 | 是否维修方法没有解决根因 |
| 同一管理漏洞 | 是否标准、培训、审核长期缺失 |

判断标准：

> **重复故障不能再按普通维修工单关闭，必须升级为RCA或RCFA。**

---

## 四、使用场景

### 1. 重大设备故障

适用于：

* 主线长时间停机；
* AA/A类关键设备故障；
* 安全环保质量风险故障；
* 高价值备件损坏；
* 修复时间长、损失大的故障；
* 对生产计划和交付造成重大影响的故障。

### 重大故障RCA重点

| 内容 | 要求 |
| --- | --- |
| 故障事实 | 时间、设备、部位、工况、损失清楚 |
| 过程还原 | 故障前、中、后过程完整 |
| 技术机理 | 部件为什么失效要讲清楚 |
| 管理漏洞 | 点检、PM、备件、维修、操作标准是否失效 |
| 防再发 | 措施必须有责任、期限、验证 |
| 横展 | 同类设备和同类部件必须排查 |

判断标准：

> **重大故障不能只靠5Why表格交差，必须进行事实和机理充分支撑的RCA。**

---

### 2. 重复故障

适用于：

* 同一故障一个月发生多次；
* 同一设备同类故障连续发生；
* 同一部件重复更换；
* 同类设备发生相似故障；
* 每次处理措施相同但问题反复出现。

### 重复故障RCA重点

| 内容 | 追问 |
| --- | --- |
| 历史工单 | 过去几次怎么修、换了什么、措施是否相同 |
| 故障模式 | 每次是否同一种失效模式 |
| 对策有效性 | 原来的对策为什么没有防住 |
| 标准更新 | 上次故障后点检、PM是否调整 |
| 横向展开 | 同类设备是否同步检查 |
| 验证周期 | 故障是否在验证期内复发 |

判断标准：

> **重复故障的核心不是再分析一次，而是分析为什么上一次分析和措施没有起作用。**

---

### 3. PM后仍然发生故障

适用于：

* 刚点检完就故障；
* 刚保养完就故障；
* 刚检修完就复发；
* PM计划完成率高但故障不下降；
* 设备故障发生在PM周期内。

### RCA重点追问

| 方向 | 追问 |
| --- | --- |
| PM任务 | 是否对应本次故障模式 |
| PM方法 | 是否能发现或预防该失效 |
| PM周期 | 是否短于P-F间隔 |
| PM标准 | 是否有正常/异常基准 |
| PM执行 | 是否真实执行并记录 |
| PM质量 | 是否存在保养诱发故障 |
| PM优化 | 是否需要PMO调整任务和周期 |

判断标准：

> **PM后故障不是偶然信号，而是检验PM任务有效性的关键证据。**

---

### 4. 故障原因跨专业

适用于机械、电气、液压、仪表、工艺、操作、备件、维修质量多因素交织的故障。

例如：

* 液压动作异常，可能涉及油液污染、阀卡滞、传感器信号、程序逻辑、压力设定；
* 电机烧损，可能涉及过载、散热、润滑、绝缘、电源波动、保护设定；
* 皮带撕裂，可能涉及跑偏、导料槽、清扫器、张紧、托辊、物料冲击；
* 轴承频繁损坏，可能涉及润滑、密封、安装、对中、载荷、备件质量。

判断标准：

> **跨专业故障不能由单一人员凭经验分析，必须组织设备、生产、工艺、点检、维修和必要的供应商共同参与。**

---

### 5. 故障影响安全、环保和质量

适用于：

* 安全联锁失效；
* 液压油、煤气、蒸汽、酸碱介质泄漏；
* 环保除尘、排放、收集系统故障；
* 关键质量设备异常；
* 检测系统误判或失效；
* 保护装置旁路或失效。

判断标准：

> **涉及安全、环保、质量风险的故障，RCA必须从风险控制和管理体系角度追溯，不能只做设备维修原因分析。**

---

## 五、使用步骤

### 第一步：明确是否触发RCA

并非所有故障都需要完整RCA，但以下情况必须触发。

### RCA触发条件

| 触发条件 | 是否触发 |
| --- | --- |
| 重大安全环保质量风险 | 必须 |
| 主线长时间停机 | 必须 |
| AA/A类设备重大故障 | 必须 |
| 重复故障 | 必须 |
| 高价值备件提前损坏 | 必须 |
| PM后短期故障 | 必须 |
| 维修后复发 | 必须 |
| 一般低损失偶发故障 | 可简化分析 |
| 低风险易恢复故障 | 可用EWO记录即可 |

判断标准：

> **RCA资源要聚焦重大、重复、高损失、高风险和有学习价值的故障。**

---

### 第二步：收集事实和证据

RCA必须从事实开始。

### 事实收集清单

| 事实类型 | 内容 |
| --- | --- |
| 故障现象 | 设备、部位、报警、异常状态 |
| 时间信息 | 发生、发现、报修、修复、恢复时间 |
| 工况信息 | 负荷、速度、温度、压力、品种、班次 |
| 部件证据 | 损坏部件、失效形态、照片 |
| 点检记录 | 故障前是否有异常记录 |
| PM记录 | 最近保养、检修、润滑、紧固情况 |
| 操作记录 | 参数、启停、调整、异常操作 |
| 维修记录 | 历史维修、换件、复发情况 |
| 备件信息 | 型号、批次、寿命、供应商 |
| 监测数据 | 振动、温度、油液、电流、压力趋势 |

判断标准：

> **没有事实证据的RCA，本质上只是经验讨论。**

---

### 第三步：还原故障过程

故障过程要按时间线还原。

### 故障时间线模板

| 时间 | 事件 | 证据 |
| --- | --- | --- |
| 08:10 | 设备运行正常 | 运行记录 |
| 08:35 | 温度开始上升 | 测温记录 |
| 09:00 | 操作工发现异响 | 交接记录 |
| 09:15 | 设备报警 | PLC报警 |
| 09:20 | 停机报修 | EWO工单 |
| 09:35 | 维修到场 | 工单记录 |
| 10:20 | 拆检发现轴承损坏 | 现场照片 |
| 11:00 | 更换轴承恢复 | 维修记录 |

判断标准：

> **过程还原越清楚，因果关系越容易验证；过程不清，5Why容易跳结论。**

---

### 第四步：分析故障机理

设备故障RCA必须讲清楚故障机理。

### 故障机理分析内容

| 分析项 | 追问 |
| --- | --- |
| 部件如何失效 | 磨损、断裂、泄漏、堵塞、过热、烧损、卡滞 |
| 失效从哪里开始 | 损伤起点、薄弱点、异常部位 |
| 失效如何发展 | 从潜在异常到功能故障的过程 |
| 哪些条件促成失效 | 载荷、温度、压力、污染、振动、润滑 |
| 是否有前兆 | 温升、振动、异响、泄漏、压差、电流 |
| 为什么最终停机 | 哪个功能丧失导致设备停机 |

判断标准：

> **设备故障RCA如果讲不清失效机理，后续对策很容易偏离真正原因。**

---

### 第五步：使用5Why但不迷信5Why

5Why可以作为RCA的一个追问工具，但必须注意三点：

1. 每一层为什么必须有事实支撑；
2. 每一层之间必须有因果关系；
3. 不能为了凑够五层而硬写。

### 正确5Why示例

| 层级 | 为什么 | 证据 |
| --- | --- | --- |
| 现象 | 辊道轴承卡滞停机 | EWO记录 |
| Why1 | 为什么轴承卡滞？ | 轴承滚道严重磨损，温度高 |
| Why2 | 为什么严重磨损？ | 油脂不足且含粉尘颗粒 |
| Why3 | 为什么油脂不足且污染？ | 润滑点无明确油量，密封防尘失效 |
| Why4 | 为什么润滑和密封问题未被发现？ | 点检表无油脂状态和密封检查项目 |
| Why5 | 为什么点检表未覆盖？ | PM任务未基于该故障模式设计 |

判断标准：

> **好的5Why不是问到第五个为什么，而是每一个为什么都能被证据支撑。**

---

### 第六步：识别根因

根因不是越深越好，而是必须满足三个条件：

1. **可解释故障发生；**
2. **有证据支持；**
3. **采取措施后能防止或显著降低再发。**

### 根因类型

| 根因类型 | 示例 |
| --- | --- |
| 技术根因 | 密封结构无法防止粉尘进入轴承 |
| 维护根因 | 润滑标准未明确油量和周期 |
| 点检根因 | 点检项目无法识别早期温升和异响 |
| 维修根因 | 安装未按对中标准执行 |
| 备件根因 | 替代件材料不适合高温工况 |
| 操作根因 | 长期超负荷运行导致部件过载 |
| 管理根因 | 故障后未更新PM标准，同类设备未横展 |
| 体系根因 | 设备故障模式未纳入维修策略管理 |

判断标准：

> **真正的根因不是写得深，而是改了以后问题不再以同样方式发生。**

---

### 第七步：验证根因

RCA必须验证根因，不能只靠会议共识。

### 根因验证方法

| 方法 | 说明 |
| --- | --- |
| 现场检查 | 对照故障部位、失效形态、环境状态 |
| 数据验证 | 温度、振动、压力、电流、趋势数据 |
| 部件分析 | 检查磨损、污染、烧蚀、断裂形态 |
| 历史对比 | 对比同类设备、历史寿命、故障记录 |
| 试验验证 | 小范围试验、参数调整、模拟确认 |
| 专家确认 | 专业工程师或供应商技术确认 |
| 横向排查 | 同类设备是否存在相同风险 |

判断标准：

> **未经验证的根因，只能称为假设，不能作为最终防再发依据。**

---

### 第八步：制定防再发措施

RCA措施必须分层设计。

### 防再发措施分层表

| 措施类型 | 作用 | 示例 |
| --- | --- | --- |
| 临时措施 | 控制当前风险 | 降载运行、增加巡检、临时防护 |
| 纠正措施 | 消除本次故障直接原因 | 更换部件、修复泄漏、恢复对中 |
| 预防措施 | 防止同类故障再发 | 修改点检标准、润滑标准、PM计划 |
| 技术改善 | 消除故障发生条件 | 改密封、加防护、优化结构 |
| 管理措施 | 修订流程、培训、审核 | OPL培训、分层审核、工单闭环 |
| 横展措施 | 防止同类设备发生 | 排查同类设备和部件 |
| 验证措施 | 确认效果 | 3个月跟踪MTBF、重复故障、异常发现 |

判断标准：

> **RCA措施必须从“修复这一次”走向“防止下一次”。**

---

### 第九步：更新标准并验证效果

RCA关闭必须包含标准更新和效果验证。

### RCA后应更新内容

| 标准或系统 | 更新内容 |
| --- | --- |
| EWO工单 | 回写原因和措施 |
| 点检标准 | 新增点位、方法、频次、基准 |
| PM计划 | 调整任务、周期、策略 |
| 润滑标准 | 更新油品、油量、周期和工具 |
| 维修标准 | 更新拆装、对中、紧固、试车要求 |
| 备件策略 | 更新型号、库存、验收、供应商 |
| 操作标准 | 更新工况控制和异常处理 |
| 培训体系 | 形成OPL和技能认证 |
| 风险清单 | 更新安全环保质量风险 |
| 同类设备 | 横展检查和措施复制 |

### 效果验证指标

| 指标 | 判断 |
| --- | --- |
| 是否复发 | 同类故障是否再次发生 |
| MTBF | 故障间隔是否延长 |
| MDT | 停机影响是否下降 |
| MTTR | 修复效率是否提升 |
| 点检异常发现率 | 是否能提前发现劣化 |
| PM有效性 | PM是否能预防或发现该故障 |
| 备件寿命 | 部件寿命是否提升 |
| 横展效果 | 同类设备是否受控 |

判断标准：

> **RCA不是报告关闭，而是措施关闭、标准关闭、效果关闭。**

---

## 七、常见问题

### 问题一：把5Why当作完整RCA

### 表现

填完5个为什么就认为RCA完成。

### 后果

缺少事实、证据、机理和验证，容易形成表格式分析。

### 纠正

5Why只是追问工具，RCA还必须包含：

* 事实收集；
* 故障过程还原；
* 失效机理分析；
* 根因验证；
* 防再发措施；
* 标准更新；
* 效果验证。

---

### 问题二：每一层Why之间没有因果关系

### 表现

上一层写“轴承损坏”，下一层直接写“点检不到位”。

### 纠正

中间必须补充机理：

* 轴承以什么方式损坏；
* 为什么发生磨损、剥落或烧蚀；
* 润滑、污染、载荷、安装是否异常；
* 为什么这些异常未被发现。

判断：

> **5Why不是写五句话，而是建立一条证据支撑的因果链。**

---

### 问题三：根因写成“人员责任心不强”

### 表现

分析最后落到员工不认真、责任心不强、执行不到位。

### 纠正

继续追问：

* 标准是否清楚；
* 工具是否具备；
* 时间是否安排；
* 培训是否有效；
* 是否有确认机制；
* 异常是否有人响应；
* 审核是否发现偏差。

---

### 问题四：只做技术分析，不做管理闭环

### 表现

找到了部件失效原因，但没有更新点检、PM、润滑、维修标准。

### 纠正

RCA必须形成管理闭环：

* 故障模式进入PM任务；
* 早期异常进入点检标准；
* 维修方法进入作业标准；
* 防再发进入审核机制。

---

### 问题五：对策没有验证

### 表现

措施完成后，报告关闭，但不知道是否有效。

### 纠正

必须设置验证周期和指标：

* 是否复发；
* MTBF是否提升；
* 停机时间是否下降；
* 异常是否提前发现；
* 备件寿命是否延长；
* 同类设备是否受控。

---

### 问题六：RCA只由维修人员完成

### 表现

维修人员写报告，生产、点检、工艺、质量、备件不参与。

### 后果

只能看到维修视角，看不到工况、操作、标准、备件和管理问题。

### 纠正

重大和重复故障RCA应由跨部门小组完成：

* 生产；
* 点检；
* 维修；
* 工艺；
* 质量；
* 安全；
* 备件；
* 必要时供应商或设计人员。

---

## 八、类似工具区别

### 1. RCA与5Why的区别

| 项目 | RCA | 5Why |
| --- | --- | --- |
| 属性 | 系统性根因分析方法 | 因果追问工具 |
| 深度 | 事实、机理、证据、体系、验证 | 连续追问原因 |
| 适用 | 重大、重复、高损失故障 | 简单问题或RCA中的追问环节 |
| 输出 | 根因、防再发、标准更新、效果验证 | 原因链和对策 |
| 风险 | 分析周期较长 | 容易跳步和主观化 |
| 关系 | RCA可使用5Why | 5Why不能替代完整RCA |

---

### 2. RCA与鱼骨图的区别

| 项目 | RCA | 鱼骨图 |
| --- | --- | --- |
| 重点 | 找到经过验证的根本原因 | 展开可能原因 |
| 适用 | 根因确认和防再发 | 原因发散和分类 |
| 输出 | 根因和措施 | 可能原因清单 |
| 关系 | 鱼骨图可作为RCA的原因展开工具 | RCA需要对鱼骨图中的原因进行验证 |

| 项目 | RCA | 故障部件分析 |
| --- | --- | --- |
| 重点 | 系统追溯根因 | 分析失效部件和失效模式 |
| 范围 | 技术、检测、维护、管理、体系 | 部件损伤、寿命、工况、安装、备件 |
| 关系 | RCA需要部件分析作为证据 | 部件分析可作为RCA输入 |

### 4. RCA与EWO的区别

| 项目 | RCA | EWO |
| --- | --- | --- |
| 重点 | 深入分析根因 | 故障维修闭环记录 |
| 适用 | 重大、重复、高损失故障 | 突发故障和维修事件 |
| 输出 | 根因、防再发、标准更新 | 故障记录、维修措施、关闭确认 |
| 关系 | EWO可触发RCA | RCA结果应回写EWO和标准 |

---

### 5. RCA与PMO的区别

| 项目 | RCA | PMO |
| --- | --- | --- |
| 重点 | 分析故障为什么发生 | 优化PM任务是否有效 |
| 输入 | 故障事件、证据、失效机理 | PM任务、故障历史、维修策略 |
| 输出 | 根因和防再发措施 | 优化后的PM任务和周期 |
| 关系 | RCA发现PM失效原因 | PMO吸收RCA结果优化维护策略 |

## 九、落地检查清单

企业开展设备故障RCA时，可以用以下清单检查质量。

| 检查项目 | 判断标准 | 是/否 |
| --- | --- | --- |
| 是否明确RCA触发条件 | 重大、重复、高损失、高风险故障清楚 |  |
| 是否收集事实证据 | 现象、照片、部件、数据、记录完整 |  |
| 是否还原故障过程 | 时间线和事件链清楚 |  |
| 是否分析故障机理 | 部件如何失效、功能如何丧失清楚 |  |
| 是否使用5Why但不跳步 | 每层因果关系有证据 |  |
| 是否区分技术、检测、管理原因 | 不只停留在直接原因 |  |
| 是否验证根因 | 根因不是会议猜测 |  |
| 是否制定具体措施 | 对象、动作、责任、期限、标准清楚 |  |
| 是否避免空泛对策 | 不只写加强培训、加强点检 |  |
| 是否更新点检和PM | RCA结果进入标准体系 |  |
| 是否横展同类设备 | 共性风险已排查 |  |
| 是否设置效果验证 | MTBF、复发、停机、寿命有跟踪 |  |
| 是否沉淀知识 | OPL、案例库、培训完成 |  |
| 是否形成闭环 | 措施关闭、标准关闭、效果关闭 |  |

## 十、总结判断

RCA根因分析，是专业维护PM和可靠性管理中解决重复故障、重大故障和高损失故障的关键工具。

它解决的是一个核心问题：

> **设备故障发生后，企业是停留在“问了几个为什么”，还是能够真正找出故障为什么发生、为什么没发现、为什么没预防、以后如何不再发生？**

如果设备故障分析只停留在5Why：

* 容易形成表格式分析；
* 容易跳过故障机理；
* 容易把原因写成人员问题；
* 容易用空泛对策关闭报告；
* 点检和PM标准不会真正优化；
* 重复故障仍然反复发生；
* 维修经验无法转化为体系能力；
* 可靠性管理难以提升。

企业开展RCA，要坚持六个判断：

1. **5Why是工具，不是RCA全部；**
2. **RCA必须从事实和证据开始，不能从结论开始；**
3. **设备故障必须讲清失效机理，不能只写部件损坏；**
4. **RCA要同时追问故障为什么发生、为什么没发现、为什么没预防；**
5. **RCA措施必须具体、可执行、可验证，不能停留在加强管理；**
6. **RCA关闭必须包含措施关闭、标准更新、横向展开和效果验证。**

最后给出本文的核心判断：

> **RCA根因分析的本质，是把设备故障从“修好了”推进到“想明白了、改到位了、标准更新了、同类风险受控了”。**

5Why可以帮助我们开始追问，但真正的RCA要求我们拿出事实、看懂机理、验证原因、修正体系。

设备故障不能只问五个为什么，更要问清三个关键问题：

**为什么故障发生？**  
**为什么没有提前发现？**  
**为什么现有管理体系没有防住？**

只有这三个问题回答清楚，设备故障分析才会从填写表格，走向真正的根因治理和可靠性提升。
