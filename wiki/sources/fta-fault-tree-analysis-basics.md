## Summary

本文档介绍了故障树分析（Fault Tree Analysis, FTA）的基础知识，定义其为一种自上而下、演绎式的可靠性与风险分析工具。文章详细阐述了 FTA 的核心作用（定位根源、风险分级、量化风险、指导改善、体系审核）、标准符号体系（事件符号与逻辑门）、五步分析法（确定顶事件、梳理边界、搭建故障树、求解最小割集、评价与改善），并通过“输送皮带无故停机”的示例展示了如何识别单点失效与多条件叠加故障。此外，文档还列举了现场使用 FTA 时的常见误区，如顶事件定义模糊、逻辑门误用及忽略人为失误等。

## Key Claims

- **定义与方法论**：FTA 是一种从顶事件（不期望发生的单一故障）出发，逐层向下拆解至底事件（基本原因）的演绎式分析工具，使用与、或、非等逻辑门构建树形逻辑图。
- **核心作用**：
  - **定位根源**：区分“单一诱因”和“多条件叠加”故障。
  - **风险分级**：通过识别最小割集（Minimal Cut Set）找到最薄弱环节，割集包含底事件越少，风险越高。
  - **量化风险**：代入零部件失效率计算顶事件发生概率。
  - **体系审核**：满足 ISO9001、IATF16949 等标准稽核要求。
- **标准符号**：
  - **事件符号**：矩形（中间事件）、圆形（底事件）、菱形（未展开事件）、房形（条件事件）。
  - **逻辑门**：或门（OR，任一输入发生即输出）、与门（AND，所有输入同时发生才输出）、禁门（限定条件触发）、异或门（仅一个输入发生才触发）。
- **五步分析法**：
  1. **确定顶事件**：描述需精准、边界清晰（如“冲压机滑块意外下行”而非“设备异常”）。
  2. **梳理边界与假设**：明确分析范围、假设条件（如正常供电）及数据来源。
  3. **搭建故障树**：逐层提问“造成故障的直接原因”，独立原因用或门，叠加原因用与门，直至底事件。
  4. **求解最小割集**：找出足以触发顶事件的最小底事件组合，单点失效（单元素割集）为最高风险。
  5. **评价与改善**：定性排序优先整改单点失效；定量计算概率；针对薄弱项增加点检、冗余设计或修订 SOP。
- **示例分析**：以“输送皮带无故停机”为例，识别出“电机线圈烧毁”、“供电缺相”、“急停按钮误触发”、“PLC 输出点损坏”为单点失效高风险项；“异物掉入”且“过载保护传感器失效”为双条件叠加，风险相对较低。
- **常见误区**：顶事件定义模糊、混淆与/或门逻辑、无限拆解导致重点丢失、只画图不落地改善、忽略人为失误和环境因素等底事件。

## Connections

- [[预测性维护]] — FTA 提供的故障因果逻辑和最小割集分析可作为预测性维护策略制定的基础，帮助识别关键监测点。
